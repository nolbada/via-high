# 교과서 본문 → 기준 데이터 (기준 사례: 금천고1 공통영어2 미래엔 김성연, 3과 43문장·4과 42문장)

스크립트·데이터: PC 스킬모음/261018_금천고_빌더스크립트.zip (공통_문장데이터/, 어휘_*/ 안 polyparse.py 등). parse.py·map.py·lib.py는 261017_금천고기말_작업파일.zip(work/)에 있다.

## 시작 전에 먼저 말할 원본
1. 교과서 본문 영어 + 출판사 한글 해석. 금천 실제 입력은 학원 hwpx였다: 어법선택 hwpx(교과서 본문 + 출판사 해석 + 어법 괄호 [a / b]), 빈칸연습 hwpx 우리말·영어(영문 + 해석, 정답 단어는 굵은 글씨 charPrIDRef=29 또는 ______), WORD TEST hwpx(단어장·유의어·반의어·다의어). 사진·교과서 PDF에서 시작한 흔적은 참고 파일에 없었다. 확인 필요: 최초 본문 타이핑 출처.
2. 시험 범위(과, 본문만인지), 소제목이 교과서에 있는지, 출판사 정식 명칭.

## 두 가지 기준 데이터
- cards_final.json (마스터): {"3":[[소제목,"영어 조각 / 조각","한글 조각 / 조각"],…],"4":[…]}. 슬래시 조각이 들어 있는 좌본문우해석 원천. 규칙은 gimal-jwa-pdf.
- sentences.json: {"3":{"en":[…],"ko":[…],"sec":[…]},"4":{…}}. 문장 단위(슬래시 없음). 어휘·요약문·순서배열·빈칸 앱의 공통 입력이고 문장 번호(0부터 인덱스)로만 참조한다.
  - en = cards 영어에서 " / "를 공백으로 바꾸고 문장 끝에 붙은 다음 소제목("… ③ Maud Lewis")을 뗀 것.
  - ko = 출판사 해석(자연스러운 해석)을 "~다"체로 바꿔 문장별로 나눈 것 (nat.json 문단을 "n. " 번호로 분할한 것과 전체 일치, 실측).
  - sec = 소제목에서 ①를 뗀 이름. 금천 3과: 도슨트의 인사 (Intro) 5, Bill Traylor 11, Maud Lewis 13, Anna Ancher 14. 4과: 신경 임플란트와 AI (Intro) 4, 의료 분야 활용 7, 미래 전망 10, 윤리적 문제 9, 신경 윤리와 댓글 12. 교과서에 소제목이 없으면 내용에 맞춰 붙인다(4과는 직접 붙임).
- sentences.json 생성 스크립트는 참고 파일에 없었다(위 관계는 대조로 확인). 확인 필요: 새 학교는 cards_final.json에서 생성 스크립트를 새로 만들어 항상 같이 갱신할 것(수작업 이중 관리 금지).

## 쪼개는 순서
1. hwpx는 zip이다. 풀어서 Contents/section*.xml을 읽는다(parse.py/parse4.py): <hp:lineBreak/>→줄바꿈, <hp:t> 텍스트만 모음, 미주(endNote)는 \x00…\x01로 표시, 굵은 run(charPrIDRef=29)은 **…**로 감싼다 → ws.json / ws4.json(문단 목록). 다른 hwpx에서는 굵은 글씨의 charPrIDRef 번호가 다를 수 있다(header.xml로 확인).
2. 단어장 hwpx는 문단 단위로 평문화(agentC/h4/parse.py, 도형은 §[…]§ 표시)해 w4.txt를 만든다. polyparse.py는 w4.txt의 줄 범위 [1104:1316]와 단어 20개 목록을 직접 박아 놓았으니 새 학교에서는 반드시 고친다. 다의어 결과: poly3.json, poly4.json({단어:{w,mean[],ex[[영,한]]}}). sec1_lines.txt는 3과 단어장 줄(문장 아님), dui.txt는 3과 다의어 원문 줄이다. cut.py는 본문 쪼개기가 아니라 앱 HTML에서 "본문 외 지문" 섹션과 3과 33번·4과 47번 이후 어법 문항을 지우는 후처리다.
3. 본문(교과서 문장)을 소제목별로 나누고 슬래시 조각을 만든다(규칙: gimal-jwa-pdf. 영어 n번째 조각=한글 n번째 조각, 동사 조각은 한글도 동사까지, 1~2단어 부사어 안 끊기, 짧은 덩어리 안 쪼갬, 후치수식 관형형). 이 최초 조각화는 Claude가 직접 했다. 확인 필요: 당시 스크립트 없음.
4. 활동지 문단과 문장의 대응표를 만든다. hwpx 한 문단에 문장이 둘일 수 있다. 금천 3과는 문단 40개 ↔ 문장 43개(align.json: {"0":[0,1],"2":[3,4],"37":[39,40],…}). 4과는 hwx4.py 안 al 딕셔너리로 대응(문단 14~44 → 문장 i-3 등). 확인 필요: 4과 대응의 나머지 예외(EXTRA).
5. 본문 외 지문(Deep Learning 등), After Reading, 그림 설명 줄은 문장에서 뺀다.

## 알려진 함정
- 3과 sentences.json 인덱스 5 영어가 잘려 있다: "The first artist we're going to examine is" (한글은 "…Bill Traylor이다."). cards_final에는 "…is Bill Traylor"로 있다. 앱이 이 문장을 쓰기 전에 고친다. 4과는 영어 불일치 0건.
- sent3.json은 구 초안이다. 영어 4·15·28번에 다음 소제목 이름이 붙어 있고, 한글 30번에 두 문장이 합쳐져(…등장한다는 점이다. 3.1859년…) 42개뿐이다. 쓰지 않는다.
- 마침표 정규화: sentences.json 영어는 끝 마침표가 거의 없고(3과 1/43, 4과 3/42) 한글은 거의 다 있다(43/43, 42/42). cards 조각은 영어·한글 모두 끝 마침표가 없다. 대조할 때는 양쪽 끝 공백과 .?! 를 떼고 비교한다. 화면·PDF에 낼 때는 영어·한글 모두 마침표(?, ! 포함)를 붙인다. hwpx 원문은 ’(둥근 따옴표), sentences.json은 '(곧은 따옴표)이므로 비교 전에 통일한다.
- PDF에서 거꾸로 되살린 cards(map.py/lib.py)에는 "heart- warming" 같은 줄바꿈 공백과 한글 띄어쓰기 오류가 있다(kiwipiepy로 복원). 가능하면 JSON을 마스터로 두고 PDF에서 되살리지 않는다.
- 출판사 해석이 "~합니다"체면 "~다"체로 바꾼다. this/it이 앞 문장을 받으면 "이것은(=지시대상)".

- 과별 문장 수와 소제목별 문장 수(위 숫자)가 hwpx·교과서와 일치. 한글 연결(공백 제거)이 출판사 해석 문단과 일치. sec 순서가 ①②③… 이고 소제목이 문장 중간에 끼지 않음.
- 활동지 문단 수 ↔ 문장 수 대응표(align)로 빈칸 정답 단어가 해당 문장에 실제 포함되는지.
- 독립 에이전트에게 교과서 원문과 영어 단어 단위로 대조시킨다. 기준 데이터가 바뀌면 파생 자료(PDF, 클래스카드, 빈칸 hwpx, 정답 앱)를 모두 다시 만든다.
