# 00 시작은 여기 · 고등 학생 앱 처음부터 끝까지 (261019)

새 학교·새 학생의 진도표(앱)를 만들 때 **이 문서 하나만 처음부터 끝까지 따라가면 된다.**
각 자료를 만드는 법은 아래 단계에서 부르는 "부품 문서"에 있다. 이 문서와 부품 문서가 다르게 말하면 **이 문서가 이긴다.**
(261018 가이드의 열기코드·개인코드·홈 잠금 방식은 261019부터 쓰지 않는다. 학생이 자기 폰에서만 진도를 관리하고, 선생님은 진도표·열기코드를 만지지 않는다. 자료 만드는 부품 문서는 그대로 쓴다.)

모든 문서는 같은 모양이다: **한 줄 요약 → 필요한 것 → 하는 일 → 끝났다는 신호 → 하지 말 것.** 새 부품 문서를 만들 때도 이 다섯 칸을 지킨다. (양식: 맨 아래 「문서 양식」)

## 처음 쓰는 분 먼저 읽기 (깃허브를 몰라도 된다)
깃허브 작업(복사·올리기)은 Claude가 한다. 사람은 **자료를 건네고, 결과를 눈으로 확인하고, 링크를 학생에게 보내는 일**만 한다.
1. Claude에게 이 폴더(`스킬모음`)를 열어 주고 말한다.
   > "스킬모음의 `261019_00_고등_시작은여기`를 그대로 따라서 ○○고 ○학년 앱을 만들어줘. 필요한 자료부터 말해줘."
2. Claude가 1단계 목록대로 필요한 자료를 말해 준다. 그 파일을 건네면 된다.
3. 끝나면 Claude가 학교 주소(`https://nolbada.github.io/via-high/h/<폴더>/`)를 준다. 열어서 달력이 보이는지 확인하고 학생에게 보낸다.
같이 있어야 하는 것: 이 폴더 전체, 저장소 `nolbada/via-high` 에 올릴 수 있는 권한.
기준 사례(그대로 복제): 고1 `h/jusung-go1/`·`h/cheongseok-go1/`·`h/geumcheon-go1/`, 고2 `h/jusung-go2/`·`h/cheongseok-go2/`·`h/geumcheon-go2/`.

## 1단계. 필요한 자료 받기 (시작 전에 모두 말해 달라고 한다)
- 학교·학년·출판사·교과서 이름, 시험 범위(과, 마지막 Culture Notes 포함 여부), 시험일.
- 학생 수와 이름(이름·개인 링크는 공개 저장소에 두지 않는다. 구글 시트 "학생 개인링크·열기코드 (공동관리)"에만).
- 과별 좌본문우해석(슬래시 조각), WORDS(어휘·유의어·반의어·다의어), 내용정리 플러스(문법 강조·TF·요약문).
- 어법선택·Check·동사형·빈칸 영어 워크북 hwpx(정답이 들어 있는 것), 예상문제 1~4회 정답.
- 지난 시험지(있으면 출제 경향 먼저).
- 수업 요일: 기본은 월·수·토 고정.
- 모의고사: 시험 범위 지문 목록(없으면 "준비 중"으로 두고 나중에 채운다).
빠진 게 있으면 **시작 전에** 말한다. 작업 중간에 없다는 걸 알게 되면 되돌릴 일이 생긴다.

## 2단계. 일정 확정 (선생님과 먼저 합의)
부품 문서 `261019_high-schedule` 의 표를 채워 선생님에게 보여 준다. 학생마다 일정이 바뀌는 일이 잦으니 **DAY 표가 합의되기 전에는 3단계 이후를 시작하지 않는다.**
- 학생이 정한 속도(예: "4과는 2회 안에")를 그대로 회차 수로 옮긴다.
- 시험 기간은 달력에 빨간색으로 넣는다.

## 3단계. 기준 데이터
과마다 지문 id(`z1~zN`)와 좌본문우해석 조각을 확정한다. 기준이 흔들리면 전부 다시 한다. 기준이 바뀌면 파생 자료를 다 같이 고친다.
덩어리(part)는 `parts.js` 에서 정한다. 한 회차 = 한 덩어리, 문장 수가 비슷하게. 교과서 본문 ❶~❼ 중 Culture Notes까지 범위면 마지막 덩어리에 넣는다.

## 4단계. 학습 활동 페이지 (앱 안에서 푸는 것) — 에이전트 병렬
활동 순서와 이름은 고정이다: **어휘 → TF → 어법선택 → 한글 순서 → ABC 순서 → 문장삽입 → 어색한 곳 → 빈칸추론.**
- 모두 인식·고르기(객관식). 스펠링 쓰기·틀린 곳 고치기는 종이로 한다.
- 한 문제씩 제출→확인→다음. 이어풀기가 된다. 홈(목록)으로 가기가 매끄러워야 한다.
- 매번 다른 문제인 활동에는 "(매번 다른 문제)" 표시.
- 모든 페이지가 `?part=N` 을 받아 그 범위만 보여 준다. 오답 노트 훅을 넣는다(→ 6단계 앱 틀).
에이전트 한 묶음 = 한 출력 폴더. 이전 학교 폴더를 복사해 새 데이터로 바꾸는 방식이 가장 빠르다. 에이전트 보고는 참고일 뿐, 마지막에 직접 열어 대조한다.
**자료가 모자라면 억지로 만들지 않고 해당 칸을 숨긴다**(`CNT` 를 0 으로). 만들 수 있는데 안 만든 것과 자료가 없어 못 만든 것을 구분해 선생님께 보고한다.

## 5단계. 답안지 페이지 — 에이전트 병렬
부품 문서 `261019_high-answer-keys` 를 따른다. 답안지 탭의 **기본 순서는 모든 학교 같다:**
1 빈칸 우리말 → 2 어법선택 → 3 동사형 → 4 Check → 5 빈칸 영어 → 6 예상문제 1~4회.
(어색한 곳 찾기는 앱 학습 영역에 있으니 답안지에서 뺀다.) 토글은 한 단계만: 교과서 3과 / 교과서 4과 / 모의고사 / 플러스 자료 (그 아래에 또 3과·4과 토글을 두지 않는다). 정답 파일은 hwpx 공식 정답과 전수 대조한다.

## 6단계. 앱 틀 조립
부품 문서 `261019_high-app-3tab` 를 따른다. 결과물: 학교 폴더 `h/<학교>/` 한 폴더.
- 3탭: 원문 / 답안지 / 오늘의 학습(항상 첫 화면). **탭 안에는 제목·설명 문구를 넣지 않는다**(아래 탭 버튼 이름만).
- 용어: "교과서 3과", "교과서 4과" 로 통일(괄호 표기 금지).
- 오답 노트(`wrong.js`·`wrong.html`)와 최종점검("틀린 문제 · 약한 유형 골라 풀기") 포함.
- 원문 탭(고1)의 보기 방식: **좌본문 우해석 / 주요 문장 성분 분석(핵심 7문장 기본·심화) / 동사형 말하기**(연습 앱 연결, "학원에서 시험으로 봐요" 안내 한 줄).
- 전체 랜덤 N문항(2회독용): 설계는 app-3tab 문서의 「랜덤 문항」.

## 7단계. 독립 검수 (Opus, 읽기 전용) 후 고치기
검수 10항목:
1. 모든 링크(원문·답안지·활동)가 실제 파일로 이어진다
2. 진도 키(`L4p1:voc`, `key:L3:dongsa` …)가 앱과 페이지에서 같다
3. 이전 과·옛 학교 흔적이 없다
4. 영어에는 한글 뜻이 붙어 있다(유의어·반의어 보기는 푼 뒤에만)
5. 정답이 hwpx 공식 정답과 전수 일치한다
6. 빠진 번호·해설이 없다
7. 폰 너비(390px)에서 가로 스크롤 0, 콘솔 오류 0
8. 일정표(ROAD·VIS·달력 날짜)가 2단계에서 합의한 표와 같다. 월·수·토가 맞고 시험일이 빨갛다
9. 0문항 칸은 숨겨져 있고, "준비 중" 칸은 안내 문구가 있다
10. "완성 도장", K/S/V시그널, A/B/C 서열 표기, 탭 제목·설명 문구가 없다
지적이 나오면 고치고 고친 부분만 다시 확인한다.

## 8단계. 올리기와 전달
`git add … && git commit … && git push origin HEAD:main` (커밋 끝에 시스템이 준 Co-Authored-By, Claude-Session 줄).
반영에 1~2분. 주소 뒤에 `?x=숫자`를 붙여 열림을 확인한다. 다른 학교 폴더는 건드리지 않는다.
학교마다 따로 주소를 주고 전체 학교 모음 페이지는 만들지 않는다.
학생 이름·개인 링크는 구글 시트에만 적는다(Claude는 시트를 직접 못 고치므로 붙여넣을 줄을 만들어 준다).

## 부록 A. 학생 한 명이 일정을 바꿔 달라고 할 때
학생마다 속도가 다를 수 있다(주성고1 이시온은 일정이 여러 번 바뀌었다). `ROAD`·`VIS`·덩어리(parts.js)·CNT 만 고친다.
1. 합의된 날짜와 회차 수를 표로 먼저 적는다(예: 10/19·21 = 4과 1~2회, 10/24 = 3과 1회, 10/26·28·31 = 3과 2~4회, 11/2~11/21 = 모의고사 9회, 11/23~ = 최종점검).
2. 교과서 덩어리 수가 바뀌면 `parts.js`(예: L4 3덩어리→2덩어리)와 CNT(합산, ABC는 최대 6)를 같이 바꾼다.
3. 달력 시험일(`EXAMD`)과 최종점검 문구를 확인한다.

## 부록 B. 새 과를 추가할 때
3→4→5단계를 그 과만 하고 `SEC`·`KEYS`·`CNT`·`parts.js` 에 줄을 더한다.

## 부록 C. 지금 비어 있는 것 (261019 기준)
- 모의고사(26년 10월) 활동·답안지: 시험 이후에 채움. 최종점검은 오답 노트가 쌓이면 동작.
- 3과 문법 분석·주요 문장 15 (원문 탭), 학교별 확인 항목(다의어 일부, 해설 문장 훑어보기).
- 전체 랜덤 N문항, 원문 탭 동사형 버튼: 구현 중이면 app-3tab 문서의 상태 표를 확인.

## 문서 양식 (모든 스킬 문서가 같은 모양)
```
# <이름> (YYMMDD)
## 한 줄 요약
## 필요한 것        (자료·앞 단계 결과)
## 하는 일          (번호 순서)
## 끝났다는 신호    (눈으로 확인할 수 있는 것)
## 하지 말 것       (이 학교들에서 실제로 틀렸던 것)
```
파일 이름: `YYMMDD_<이름>_SKILL.md` (순서가 있는 안내는 `YYMMDD_00_…md`). 날짜는 만든 날 최신을 붙이고, 예전 것은 폴더 `delete/` 로 옮긴다.
