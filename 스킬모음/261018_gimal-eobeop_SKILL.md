# 어법선택 정답·해설 + 시험 앱 (기준: 금천고1 공통영어2 미래엔 김성연 3·4과)

결과: h/<학교>/<과>/eobeop.html, eobeop-test.html. 3과 32문항(괄호 47칸), 4과 43카드(93칸; 12~15번은 도표 4줄이라 한 카드 id q12-15).

## 시작 전에 먼저 말할 원본
1. 워크북 '어법 선택형 연습' hwpx(과별 1개). 문항마다 괄호 [A / B], 정답은 미주(endnote)와 맨 뒤 Answer Key 구역에 있다.
2. 좌본문우해석 카드(슬래시 영어 조각+한글 조각, 소제목 ①②…): 시험 앱의 소제목 구분용.
3. 범위: 교과서 본문만. 워크북 뒤쪽 '본문 외 지문' 문항(3과 9개, 4과 약 8개)은 뺀다(시험 범위 아님).

## 1. 원본 파싱 (eb/parse_eb.py)
- hwpx는 zip. Contents/section0.xml(문제), section1.xml(Answer Key). `</hp:p>`·`<hp:lineBreak/>`는 줄바꿈, `<hp:fwSpace/>` 제거, 나머지 태그 제거 후 html.unescape해서 {과}.txt로 저장. 텍스트 상자 안 글도 포함돼야 한다. 직접 돌려 보니 단순 정규식은 소제목 상자를 빠뜨려서, 금천 때 실제로 쓴 추출 명령은 파일이 없다(확인 필요).
- 영어 문항 줄 = `\[[^\]]+/[^\]]+\]` 포함 + 영문 3자 이상. 줄 순서가 곧 문항 순서(12~15는 4줄을 한 카드로).
- 검수(parse_eb.py): 정답 해설 페이지의 정답이 그 문항 괄호의 두 보기 중 하나인지 전수 대조, 칸 수 일치. MISMATCH 0이어야 한다.
- 결과 items.json = [{n, ans[], brs[[보기1,보기2]...], ws}].

## 2. 정답·해설 페이지 eobeop.html
생성 스크립트는 남아 있지 않다(확인 필요). 완성 HTML이 기준이며 구조는 gramma-voca-haeseol 스킬(어법·어휘 고르기 카드)과 같다.
- 맨 위 '빠른정답' → 문항별 카드 `.q#qN`: 번호 배지(.no)+정답(.ans), 영어 .en(좌본문우해석 슬래시 조각 `/` 유지, 정답은 굵게+빨간 밑줄), 한글 해석 .ko, '해설' 태그 아래 괄호마다 `.pt`.
- `.pt` = ①정답(.pw 파란색) + 이유 1~2줄(.ln: 왜 이게 정답이고 다른 보기는 왜 안 되는지) + 노란 '쉬운 예' 박스(.exb: 쉬운 영어 예문+한글 뜻, 필요하면 .nt '→ 본문 …과 같은 모양').
- 영어에는 한글 뜻 병기, 표 없이 큰 글씨(본문 18px, 영어 19px) 왼쪽 정렬.
- 알려진 어긋남: 빠른정답이 '회색 번호+빨간 글자' 목록(.quick)이라 확정 규칙(번호 배지+빨간 정답 칩)과 다르다. 새 학교는 check.html의 .chip(i 배지+b 빨간 정답) 방식으로 만든다. 4과는 .pt 93개 중 .exb 87개(6개 쉬운 예 없음, 확인 필요).

## 3. 시험 앱 eobeop-test.html (eb/build_test.py → eb/html_test.py)
1. build_test.py: {과}.txt의 괄호 줄과 eobeop.html의 카드(ko·해설 .pt·정답)를 짝지어 cards{과}.json 생성. 정답 위치는 `norm(정답)==norm(보기)`로 찾고(assert), 칸 수 = 정답 수 = .pt 수를 assert. 소제목은 cards_final.json(좌본문우해석)의 영어 앞 30자 정규화 일치로 붙이고 못 찾으면 앞 문항 것을 이어 쓴다.
2. html_test.py: eobeop.html의 `<style>`(CSS0)을 그대로 재사용 + 시험용 CSS/JS를 붙여 eb/out/eobeop-test{과}.html 생성. 아이콘 link(../icon.svg, apple-touch-icon)와 '← 금천고 정답 목록' 포함.
3. 오른쪽 아래 `⌂ 목록` .homefab 추가는 푸터 HTML을 직접 끼워 넣었다(삽입 스크립트 없음, 확인 필요).

### 풀이 방식 (확정)
- 고르기만. 문제 순서는 섞지 않는다(본문 연대순을 기억하게). 소제목 `.secd` 구분.
- 괄호마다 두 버튼 `[A] / [B]`. 영어 보기에 한글 뜻은 미리 보이지 않는다.
- 한 문항의 모든 괄호를 고르면 '정답 확인' 활성. 누르기 전에는 정오 표시 없음(선택은 파란색만). 누른 뒤 정답 칸 초록, 틀린 선택은 빨간+취소선, '모두 정답이에요/틀린 칸이 있어요(n / m)', 한글 해석(.kk) + 해설(.pt) 펼침. 푼 문항은 잠김.
- 위 고정 바(#cnt): 'n / N 문제 · 정답 m / 칸수칸' + '처음부터 다시'. 마지막 문항 뒤 결과 박스에 틀린 문항 번호 링크(본문 순서).

### 이어풀기 저장 (mk5.py가 패치로 추가. 새로 만들 땐 처음부터 넣는다)
- 키 `'gk-res:'+location.pathname.replace(/[^a-z0-9]/gi,'')`, rep 플래그.
- 값 `{문항idx:{s:[칸별 고른 버튼 idx 또는 -1], d:채점여부 0/1}}`. persist()는 카드 클릭마다 저장. 채점 후에는 .sel이 사라져 pidx가 sel→ng→ok 순으로 고른 번호를 복원한다.
- 로드: 저장값이 있으면 rep=true로 칸마다 버튼 .click() 재생 → d=1이면 .go.click() → rep=false → persist() → 처음 안 푼 카드로 스크롤. '처음부터 다시'는 removeItem. 모든 localStorage는 try/catch.

## 4. 검수 (전수)
- 420px에서 scrollWidth=420, 콘솔 오류 0, 다크모드, 전 문항 정답 클릭 시 칸 수=정답 수(3과 47, 4과 93), 일부만 풀고 새로 고침→복원(금천 3과로 확인).
- 필수 대조: 시험 카드 영어(정답 대입)와 eobeop.html .en을 기호 제거·소문자로 비교. 금천 3과에서 시험 앱 #3·#13·#22 문장 앞에 워크북 소제목(Bill Traylor, Maud Lewis, Anna Ancher)이 붙어 틀린 채 올라가 있었다(4과는 일치). 파싱 때 줄 앞 소제목을 떼고 이 대조를 자동으로 돌릴 것. (#21 Maud Lewis expressed…는 정상 문장이라 지우지 않는다.)
- 소제목 매칭은 영어 앞 30자 비교라 첫 카드가 짧으면(3과 #1, 영어 첫 조각 'Welcome to the Dream Art Gallery!'가 30자 미만) 실패한다. 금천 3과 시험 앱은 #1이 소제목 없이 시작하고 '도슨트의 인사'는 #2 앞에 붙어 있다. 첫 카드는 뒤 카드의 소제목으로 채울 것.
