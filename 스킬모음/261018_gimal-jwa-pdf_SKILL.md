# 좌본문우해석 PDF (기준 사례: 금천고1 공통영어2 3·4과)

스크립트: PC 스킬모음/261018_금천고_빌더스크립트.zip. 단 이 zip에는 mkpdf2.py·padpdf.py가 없고 261017_금천고기말_작업파일.zip(work/)에 있다. 확인 필요: 한 zip으로 합칠 것.

## 이 PDF가 기준이다
좌본문우해석의 슬래시·해석이 바뀌면 파생 자료(클래스카드, 빈칸연습 hwpx, 한글/영어채우기 정답 앱, 어휘·요약문·순서배열·빈칸 앱의 문장 데이터)를 모두 다시 만든다. 순서: 마스터 JSON 수정 → PDF → 파생 자료. 문장 단위로 전수 대조한다(일부만 보지 않는다).

## 시작 전 필요한 원본
- 교과서 본문 영어 + 출판사 한글 해석(해석지 hwpx 등). 자연스러운 해석은 출판사 해석을 쓰고 직접 번역하지 않는다.
- 범위는 본문만(After Reading, 본문 외 지문, 그림 설명 줄 제외). 학교명·교과서명·과 제목·소제목.

## 입력 데이터 (work/ 폴더, 같은 폴더에서 실행)
- cards_final.json: {"3":[[소제목, 영어, 한글],...], "4":[...]}. 문장 1개 = 3칸 배열. 영어·한글 안의 슬래시 " / "가 조각 경계이고 개수가 같아야 한다. 소제목은 "② Bill Traylor"처럼 원문자 포함.
- layout.json: 과별 쪽 목록. 쪽 = [["s","①"], ["n",1], ["n",2] ...]. s는 소제목 줄, n은 소제목 안 문장 번호(소제목마다 1번부터). 문장은 순서대로 쪽에 이어 채운다(단락마다 쪽을 나누지 않음). 소제목만 쪽 맨 아래 홀로 남기지 않는다.
- nat.json: 과별 쪽당 자연스러운 해석 문단 1개. "[① 소제목] 1. … 2. …" 형태. 쪽 수는 layout과 같아야 한다.
- mkpdf2.py 안 META: 과별 (우상단 헤더, 제목, 부제). 새 학교는 여기를 고친다.

## 실행 순서
1. 빈 작업 폴더에 위 JSON + mkpdf2.py + padpdf.py를 둔다. 필요: wkhtmltopdf, pdfunite, pdfplumber.
2. `python3 mkpdf2.py` → pages.pkl (쪽별 HTML과 CSS).
3. `python3 padpdf.py` → 쪽마다 따로 렌더(pp_<과>_<쪽>.pdf)하고 문장 행 위아래 여백 변수 --p(4~40px)를 이진탐색해 내용 하단이 281mm 이하 최대가 되게 맞춘 뒤 pdfunite로 n3.pdf, n4.pdf 생성. 인자: A4, 위 16mm, 아래 7mm, 좌우 19.5mm. 마지막 쪽은 듬성하지 않게 여백 상한을 둔다(금천 4과 마지막 쪽은 18px 고정).
4. 이름 붙이기: YYMMDD_N과_좌본문우해석.pdf (날짜는 최신). 저장은 시즌창고 26-2기말_학교학년\2_만든자료\YYMMDD_교과서_좌본문우해석\ 에 한 부만. 이전 임시본·구 날짜본은 지울 파일로 알려 준다.
- mkpdf.py는 구버전(고정 여백)이다. mkpdf2.py + padpdf.py를 쓴다.
- 쪽 구성: 헤더(우측 회차명) / 제목 박스(쪽 번호 배지) / 소제목 / 2열 표(영어 73% + 한글 27%, 번호는 내어쓰기) / 1~5회독 칸 / 자연스러운 해석 문단([소제목]·번호는 파란 굵게) / memo.

## 사용자 확정 규칙 (다시 묻지 않는다)
- 글씨체: 맑은 고딕에 가장 가까운 Noto Sans CJK KR(이 환경엔 맑은 고딕 없음). 얇은 글씨(Light/DemiLight) 금지, 보통 굵기(Regular, 강조만 Bold). 확인: `pdffonts`에 Light가 없어야 한다.
- 영어 약 11pt. 주의: wkhtmltopdf는 CSS px를 약 0.576배로 줄여 찍는다. 실측: 영어 17px → 9.8pt, 19.1px → 10.9pt. 11pt를 원하면 영어 약 19px로 하고, pdfplumber로 글자 크기를 직접 재서 확인한다.
- 3과·4과 등 모든 과가 글씨 크기·간격 동일. 과마다 CSS를 바꾸지 않는다(쪽 여백 --p만 쪽별로 달라진다).
- 영어·한글 문장 끝에 마침표(?, ! 포함) 필수. 기존 구스킬의 "표에는 마침표 없음"은 폐기. 마스터 JSON은 끝 마침표가 없으므로 렌더 직전에 문장 끝(마지막 조각)에만 붙인다(권장: 마스터를 건드리지 않아 파생 자료 영향 없음). 이미 ?/!/.로 끝나면 중복 금지, 따옴표·괄호로 끝나는 문장은 확인 필요.
- 슬래시: 영어 n번째 조각 = 한글 n번째 조각(순서·내용 대응). 영어에서 동사가 나오는 조각은 한글도 동사까지 같은 조각.
- Today, However, Later, In contrast 같은 1~2단어 부사어는 뒤 조각과 합쳐 따로 끊지 않는다. 단 주어+동사가 있는 "I'm Isabel Williams," 같은 조각은 유지.
- 고등용: 짧은 덩어리를 쪼개지 않고 한 호흡으로 묶는다. 동사+목적어/보어(wanted to revive, helps a human become), 짧은 전치사구(starts with a girl, makes a deal with the tiger, dates back to the…), 분사구(people hunting)는 슬래시 없이 붙인다. 해석 동사 위치가 애매한 문장("seems that")은 슬래시 없이 한 문장.
- 후치 수식(분사·관계절)은 새 문장으로 풀지 말고 관형형: known for → "알려진", the street he observed → "그가 관찰한".
- 해석 어투 "~다" 체(기존 스킬). this/it이 앞 문장을 받으면 "이것은(=지시대상)". 영어 하이픈 단어는 공백 없이(heart-warming; PDF 추출 흔적 "heart- warming" 주의).
- 학원명은 "비타민 영어클리닉".

## 검수 (전수)
- 문장마다 영어 슬래시 수 = 한글 슬래시 수(금천 3·4과 85문장 모두 일치 확인).
- layout의 문장 수 합 = cards 문장 수, nat 문단 수 = 쪽 수(스크립트 assert).
- 각 과 PDF: 쪽마다 1쪽, 하단 286mm 이하, 좌우 여백 15~19mm, 문장 번호 연속, 모든 문장 끝 마침표, pdffonts에 Light 없음, 과별 글자 크기 동일(pdfplumber 집계).
- 독립 에이전트에게 원문 대조(영어 단어 일치, 슬래시 대응, 오역, 자연스러운 해석 문장 수·순서).

## 알려진 함정
- cards_final.json의 영어에는 PDF 추출 흔적으로 다음 소제목("… ③ Maud Lewis")이 문장 끝에 붙어 있다. mkpdf2.py가 정규식으로 떼어 낸다.
- 구 PDF에서 데이터를 되살릴 때(map.py, lib.py: 좌 405pt 미만=영어, 이상=한글, kiwipiepy로 한글 띄어쓰기 복원)는 해석 문단 번호 오인식이 생긴다. 새로 만들 때는 JSON에서 시작한다.
- 쪽당 문장이 큰 글씨에서 넘친다: 금천 layout.json은 영어 17px 기준이다. 19px로 키우면 같은 layout에서 3과가 7쪽으로 넘쳤다(실측). 11pt로는 layout.json을 다시 짜야 한다.

## 확인 필요
- 11pt·마침표 반영 최종 스크립트는 참고 파일에 없었다(mkpdf2.py는 17px/13.4px 구버전). 위 값은 구버전 실측에서 유도한 것이다.
- 11pt에서의 한글 크기(구버전 13.4px ≈ 7.7pt). 사용자 지정 없음.
- 11pt용 layout.json 재배치 방법(쪽당 문장 수를 줄여 padpdf 최소 여백 4px로 넘치지 않을 때까지 채우는 방식 추정, 미검증).
