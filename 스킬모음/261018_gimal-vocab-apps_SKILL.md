# 어휘 앱 ①~④ (과마다 4페이지: vocab1~4.html)

과 본문을 4구간으로 나눠 구간마다 한 페이지. 한 페이지에 세 유형이 섞여 나온다.
- 유의어·반의어 사지선다(보기 5개): 본문 문장에서 밑줄 친 단어의 같은/반대 뜻을 고른다.
- 본문 바뀐 문장 찾기(flip): 본문 문장의 핵심 구를 정반대로 바꾼 문장 1개를 본문 문장 몇 개와 섞어 보여 주고, 본문과 달라진 문장을 고른다. 예) highly valued → barely valued.
- 다의어: 같은 단어가 다른 뜻으로 쓰인 본문 문장을 보여 주고 뜻을 고른다. 뜻이 같은 문장이 다시 나오는 '허를 찌르는(TWIST)' 문항을 구간마다 1~2개 섞는다.

## 시작 전에 필요한 원본
- 과 본문 영어·한글(문장 단위, sentences.json).
- 어휘 목록: 유의어(SYN), 반의어(ANT), flip, 다의어(poly json). 새 학교는 과 본문에서 새로 뽑는다. 교과서 단어장 단어를 우선한다.
- 구간 나누기 범위(SECR): 문장 인덱스 구간 4개.

## 데이터 형식 (vdata.py / vdata4.py)
- SYN/ANT: (단어, 품사, 뜻, 문장 인덱스, 본문 속 형태 form, 보기 목록, 해설). form은 문장에서 실제로 찾아져야 한다(스크립트가 assert).
- FLIP: (문장 인덱스, 원래 구, 바꾼 구, 해설).
- 다의어: poly json {w, mean[], ex[(영어, 한글)]}. ex 개수와 mean 개수가 맞을 때만 정답 번호를 붙인다.
- TWIST: {구간번호: [(단어, 문장 인덱스, 형태, 뜻 번호)]}.

## 확정 규칙 (피드백 반영분)
- 보기 품사는 정답과 일치시킨다. 보기는 해당 범위 전체에서 품사가 맞는 단어로 골라 더 고급스럽게.
- 유의어·반의어 보기에는 한글 뜻을 미리 보이지 않는다. 푼 뒤에만 표시. 빌드 결과 CSS에서 `.ob small{color:var(--sub);font-size:14px}` 바로 뒤에 `.q:not(.done) .ob small{display:none}` 를 넣는다. 어휘 페이지를 다시 빌드하면 이 줄이 사라지므로 매번 다시 적용하고 8개 페이지(3·4과 각 4개)를 점검한다.
- 문제 유형(syn/ant)이 정답과 일치해야 한다. 4과에서 normal이 유의어로 물어보고 정답은 반의어였던 오류가 있었다. 빌드할 때 type을 정답 기준으로 맞춘다.
- 다의어는 같은 단어가 연달아 나오면 추측이 되므로 spread()로 섞는다(같은 단어가 gap 3 → 2 → 1 안에 다시 나오지 않게). 같은 뜻이 또 나오는 TWIST 문항을 일부러 넣는다.
- 영어에는 한글 뜻, 단어 설명은 사전식이 아니라 본문 흐름·앞뒤 연결로.
- 해설은 짧게. 결과 화면은 담백하게.

## 검수
- 모든 form이 문장에서 찾아지는가, 보기 5개 중 정답 1개, 보기 품사 일치, 보기에 한글 뜻 숨김, 가로 스크롤 0(420px), 다의어 연속 중복 0.
- 4과는 polyparse.py, relcheck.py, verify4.py 로 다의어 파싱과 관련성을 점검했다.
