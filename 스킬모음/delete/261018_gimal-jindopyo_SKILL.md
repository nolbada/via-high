# 학교별 내신 진도표 (기준 모델: 금천고1 공통영어2 2학기 기말)

기준 파일: 저장소 nolbada/via-high, 폴더 h/geumcheon-gimal/ 의 `index.html`(홈), `gate.js`(앱→홈 점수 연결), `tq7k2m/index.html`(선생님 전용 열기 코드 조회).
설계 문서(사람이 읽는 것): 저장소 맨 위 `261018_진도표_설계.md`. 이 스킬은 그것을 실제로 만드는 순서다. 자료(앱·PDF)를 만드는 순서는 `261018_00_시작은여기` 가이드와 부품 스킬(gimal-*) 쪽이다. 진도표는 그 자료들을 한 화면에 엮는 층이다.

## 0. 시작 전에 먼저 물어볼 것 (원본·결정)
1. 학교·학년·교과서, 시험 날짜(D-day), 과(단원) 목록과 과별 수업 횟수(금천: 과마다 4회).
2. 각 회차에 들어갈 카드와 순서(어떤 활동이 종이PDF, 앱, 시험인지). 회차 사이의 선후관계(예: 어법선택 PDF를 한 뒤에 어법선택 시험).
3. 학생 명단과 화면 구분: 심화+플러스 / 기본 / 관리형. (관리형 = 학원에 안 오는 학생. 종이는 토요일에 묶음으로 받아 가는지 확인.)
4. 모의고사 구간(몇 주, 지문 수, 출처 묶음)과 총정리.
5. 선생님 코드(숫자 6자리 정도).
학생 이름·등급·선생님 코드는 **공개 저장소에 절대 넣지 않는다.** 명단은 `D:\Github 어플모음\★ 내 링크\YYMMDD_학생명단_개인링크.xlsx` 한 곳에서만 관리한다.

## 1. 구조 규칙 (바꾸지 말 것)
- 학교마다 주소가 따로다: `h/<학교-영문명>/`. 전체 학교 모음 페이지는 만들지 않는다.
- 날짜로 열리지 않는다. 날짜는 D-day와 대략의 7주 지도뿐이고, 지도의 깃발은 학생의 실제 진도로 움직인다 (월수/화목 반, 학평일 수업, 속도 차이).
- 과마다 N회차. 회차 안에 번호 카드(①②③). 뼈대(모두) / 플러스(빠른 학생) / 시험 카드. 숙제 코너는 회차와 따로(세트 완료 점 3개가 목표).
- 카드 표시: 종이=`PDF`+`선생님 확인`, 앱=`앱`(채점 앱은 `70% 통과`), 시험=`시험`, 말하기 시험=`선생님 확인 필요`, 플러스=`플러스`.
- 열리는 규칙: 앱은 70% 이상 또는 두 번 해 보면 통과. 종이는 학생의 "다 했어요"(선생님은 학원에서 PDF 완성도 확인). 말하기 시험은 다음 회차 조건에서 제외. 앞 회차 뼈대를 다 끝내면 다음 회차 열림.
- 잠긴 회차·과도 **카드 목록은 보이게** 한다(흐리게+자물쇠). 남은 분량이 보여야 페이스 조절이 된다.
- 학생 화면에 이름·등급·상위/하위 표현 금지. 코스 이름은 "(기본)/(심화)"로만. "완성 도장" 같은 유치한 표현 금지.

## 2. 홈 만드는 순서
1. 기준 `index.html`을 복사해 `h/<학교>/index.html`로 둔다. 바꿀 곳: 제목, D-day 날짜, 지도의 단계(과·모고·총정리), `lesson(n)` 안의 회차·카드 목록(id는 `L<과>-<이름>`, href는 그 학교의 앱 경로).
2. 개인 코드: `CODES={'<5자리>':'s'|'b'|'c', ...}` (s=심화+플러스, b=기본, c=관리형). 코드는 영문·숫자 5자리, 학생끼리 겹치지 않게. 폰에 `gk26-code`로 저장된다(키 이름은 학교가 달라도 origin이 같아 겹칠 수 있으니 학교마다 다른 접두를 쓰는 것을 권장 — 아직 금천고만 있다).
3. 선생님 코드: `TH = sha256(선생님코드)`의 16진수. 입력하면 회차 열기·시험 확인·관리형 카드 열기·선생님 모드(화면 전환 보기).
4. 학생·단계별 열기 코드(선생님이 카톡으로 전해 주는 코드):
   - 단계 key: `3-1,3-2,3-3`(3과 2~4회차), `L4`(4과 열기), `4-1,4-2,4-3`. 과 번호는 학교에 맞게.
   - 코드 만들기: `d = sha256(선생님코드 + ':' + 개인코드 + ':' + key)`, 처음 6바이트 각각 `알파벳[byte % 31]`, 알파벳은 `23456789abcdefghjkmnpqrstuvwxyz`.
   - 홈에는 검증용 해시만 넣는다: `UH = [sha256(개인코드 + ':' + key + ':' + 열기코드), ...]`. 학생이 입력하면 홈이 같은 식으로 계산해 UH에 있는지 본다. 선생님 코드 자체는 홈 어디에도 없다.
   - 선생님 전용 조회 페이지는 `h/<학교>/<무작위6자>/index.html`(noindex). 선생님 코드를 넣고 개인코드·단계를 고르면 열기코드가 나온다. 이름 메모는 그 폰 localStorage에만. 이 주소는 학생·카페에 공유 금지, 명단 xlsx에만 적는다.
5. 관리형(c): 잠기는 카드에 `cc:1`을 주면 보이되 잠기고 "정규 수업 코스 자료예요" 중립 문구가 뜬다(문구에 돈·결제 암시 금지). 말하기 시험(tonly)은 cc 처리. 순서배열 ABC는 맛보기로 열어 둔다. 동사형 연습 앱은 정답 확인용으로 열어 둔다. 관리형 전용 화면(두 구역 분리)은 아직 설계 전.
6. 홈에서 4과(다음 과)를 잠글 때 숙제 코너도 같이 잠글지 결정한다(금천고는 현재 열려 있음).

## 3. 앱 → 홈 점수 연결 (gate.js)
- 각 앱에 `<script src="../gate.js"></script>`를 앱 스크립트 앞에 넣는다 (홈 폴더 기준 상대경로).
- 채점 앱: 끝까지 풀었을 때 **한 번만** `GK.report('<id>', 정답률%)`. 저장된 풀이를 다시 불러오는 중에는 부르지 않는다(복원 플래그). 다시 하기 후 또 끝내면 또 한 번(tries 증가).
- 숙제 앱: 한 세트 끝낼 때 `GK.hw('<id>')`. 세트 기준은 앱마다 정한다(빈칸 추론=한 판, 순서배열=한 페이지·6문제 한 판).
- 홈은 `gk26-rep`(점수), `gk26-hwauto`(숙제 점)를 읽는다. 상세는 저장소 gate.js 주석.
- 앱 id는 홈의 카드 id와 정확히 같아야 한다.

## 4. 검수 (Playwright, 390x844)
- 홈이 콘솔 오류 없이 열린다. 개인 주소 3종(s/b/c)과 코드 없음 화면이 각각 맞다.
- 잠긴 회차에도 카드가 다 보인다. 관리형에서 cc 카드가 잠기고 시트 문구가 중립이다.
- 앱을 끝까지 풀면 `gk26-rep`에 pct·tries가 기록되고 새로고침해도 tries가 안 는다. 두 번 해 보면 통과가 된다.
- 열기 코드: 선생님 조회 페이지가 낸 코드가 그 학생 주소에서만 열린다(다른 학생 코드는 거절).
- 링크 점검: 홈의 모든 href가 실제 파일/폴더로 이어진다.
- 공개 저장소에 이름·선생님 코드가 없는지 grep.

## 5. 올리기와 명단
- `git pull --rebase origin main` → 복사 → 커밋 → `git push origin HEAD:main`. 사이트 반영은 1~3분 뒤.
- 새 학교 명단: `★ 내 링크\YYMMDD_학생명단_개인링크.xlsx`에 학교별 시트(`○○ 명단`, `○○ 열기코드`)를 추가한다. 개인 주소·열기코드 표는 xlsx에 채워 준다.
- 학생에게는 개인 주소만 톡방/QR로 한 명씩. 네이버 카페 앱 안에서 연 주소와 홈 화면 앱은 진도가 따로 저장되므로 같은 곳에서 계속 열게 안내한다.

## 6. 한계 (학생·학부모에게 설명할 때)
- 진도는 학생 폰에만 저장된다. 폰을 바꾸면 처음부터(선생님이 열기 코드로 열어 줄 수 있음).
- 잠금은 "슬쩍 열어 보기"를 막는 정도다.
- 학생별 현황판은 서버가 필요해서 아직 없다.

## 7. 회차 순서 (금천고1 기준, 확정)
1회차 본문 읽고 내용 잡기(+어법선택 PDF) → 2회차 핵심 7문장·어휘②·동사형 PDF·어법선택 시험 → 3회차 예상문제 1회·동사형 말하기 시험 앞 1/2 → 4회차 예상문제 2회·말하기 시험 뒤 1/2.
원칙: **종이 활동 → (다음 회차) 그 활동의 시험**. 앞 회차 뼈대를 끝내야 다음이 열리므로 순서가 자동으로 지켜진다. 말하기 시험은 선생님 확인(다음 회차 조건에서 제외).

## 8. 아직 정해지지 않은 것
- 관리형 두 구역 화면, 동사형 전체 빠른정답표, 동사형 앱 프롬프트 md.
