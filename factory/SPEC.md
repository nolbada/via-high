# 학교 앱 규격 (기준: geumcheon-go1)

## 버전 (먼저 읽기)
쉬운 설명: 2026-10-24에 학생 앱 첫 화면의 **'유형 풀코스' 부분만** 새 모양으로 바뀌었다. 이 새 모양을 **v2**, 그 전 모양을 **v1(옛 방식)** 이라고 부른다.
v1과 v2가 갈라지는 곳은 **메인 화면(오늘의 학습)의 유형 풀코스 영역부터**다. 그 밖의 화면은 v1과 똑같다.

| 구분 | 이전 (v1, ~261023) | 지금 (v2, 261024~) |
|---|---|---|
| 첫 모습 | 지금 할 회의 유형 줄 8~9개가 바로 펼쳐져 있음 | 작은 회차 버튼 그리드만 보임(한 줄 7칸, `.sgh` 제목 + `.sgrid`/`.stb` 버튼) |
| 회 고르기 | 아래 "이전 회 / 다음 회" 버튼 | 회차 버튼을 누르면 그 회 유형 목록이 열리고, 다시 누르면 닫힘. 이전/다음 회 버튼 없음 |
| 회 표시 | 목록 제목 "유형 풀코스 · N회 (소속)" | 버튼 = 2글자 단원 뱃지(3과·4과·모의·최종) + "N회". 열린 목록 제목 "N회 (출처)". 위쪽 제목 "유형 풀코스" + 알약 "21회 중 M회" |
| 회 번호 | 전체 연번 | 그대로 전체 연번(1회부터 끝까지, 소속이 바뀌어도 번호는 이어짐. 고1·고2 21회, 주성 19회) |
| 열림 규칙 | 아무 회나 열 수 있음 | 단계식: 앞 회를 다 끝내야 다음 회가 열림 (`stState`: done 끝 / now 지금 / lock 잠금). 안내가 있는 회(`v.x`)는 잠금 |
| 끝난 회 | 목록 제목 옆 "완료" 꼬리표 | 버튼이 연한 파랑으로 채워짐(`--priL`), '끝' 같은 글자 없음 |

| 처음 연 상태 | 안 끝낸 첫 회가 자동 선택 | 아무 회도 선택 안 됨(`selNo=0`) |
| 스페셜 버튼 | 일반 배너 | 민트색 배너 `.wnb.spb` (조건 문구 굵게) |

**바뀌지 않는 것:** 달력, 이어서 풀기 카드, 오답 노트, 전체 랜덤 20문항, 기말 안내 줄, 나의 학습 기록 카드, 시험까지 큰 흐름(ROAD), 열린 목록 안의 유형 줄 모양(체크박스·파란 ✓·전체 선택/해제·"체크한 유형 이어서 풀기"), 진도 저장 키(vhp·vhbm·vhq·vhc·vhd·vhts), 활동 페이지·답안지 탭 전부.

- 코드 근거: `h/geumcheon-go1/index.html` 의 `stState`·`selNo`·그리드 렌더(`/* 선택한 회 */` 아래)·CSS(`.sgh/.sgrid/.stb/.slk/.spb`). 조각은 `snippets/stage_*.txt`·`rows.txt`·`hand.txt`(v2), 옛 조각은 `snippets/v1_*.txt`.
- 커밋: dcc852d(금천고1 v2) → 0a705f8(제목 강조·스페셜 색) → 3b53fd3(청석고1·주성고1) → 62eabae(고2 3개) → 29a405b(버튼에 '회', 목록 제목) → a2be12e(번호 이어서 표기).
- 중등도 v2 적용: 용아중2 — 저장소 `nolbada/via-mid` 의 `m/yonga-mid2/app.js`·`style.css` (커밋 9a2178e, 30642fb, 89070e1, 1~22회, 뱃지 'N과'·'최종'). 중등은 그 저장소 기준을 따르며 이 factory 로 검사하지 않는다.
- v1 구조로 새 학교를 만들었다면 `python3 factory/tools/port_v2.py <학교>` 로 v2로 바꾼 뒤 audit.py 를 돌린다.

"인증샷용", 캡처 안내, "다음에 할 활동", 번호 배지 줄, "기록 옮기기 · 선생님 확인"은 두지 않는다(기록은 구글 시트로 연동).

## 랜덤 문제 풀기 화면 (mix.html)
- 20문항을 뽑으면 묶음(유형·구간) 목록이 풀코스 줄과 같은 모양으로 나온다. 안 한 묶음은 회색 체크박스(처음엔 모두 해제), 끝나면 파란 ✓.
- 전체 선택 / 전체 해제, "체크한 유형 이어서 풀기 (N)" 버튼. 누르면 체크한 묶음을 차례로 열고, 한 묶음이 끝나면 아래에 "다음 유형: ... ›" 바가 나온다. 마지막 묶음 뒤에는 "체크한 유형을 모두 끝냈어요 · 랜덤 문제로".
- 묶음 이름을 누르면 그 묶음만 열린다. 묶음마다 "끝냈다고 표시" 버튼은 두지 않는다(활동 페이지가 끝나면 자동 표시).
- 저장: vhmx:학교 (chk = 체크 상태), 이어 풀기 목록 vhmq:학교 {r:회차, l:[{k,u,n}]}. 다음 유형 바는 wrong.js 가 그린다.

## 새 영역 추가 규칙 (모의고사 확장, 해설서 추가 등)
1. 기존 회 번호는 절대 재배열하지 않는다. 학생 기록(PG, vhc, vhd)이 번호로 저장되므로 번호가 밀리면 다른 회로 바뀐다. 새 회는 맨 뒤 번호로만 추가한다.
2. 새 활동 키는 mockp번호:유형 형식을 따르고, 기존 키 이름은 바꾸지 않는다.
3. common/prog.js는 6개 고등 학교와 기말 앱 3개가 공유한다. 새 영역 때문에 고쳐야 하면 먼저 영향 범위(9개 앱)를 알리고, 가능하면 학교별 파일이나 별도 파일에 둔다.
4. 풀코스에 유형을 추가하면 mix-pool.js도 같은 작업에서 갱신한다. 풀코스와 풀이 어긋나지 않는지는 audit 항목으로 검사한다.
5. 읽는 형태(해설서 등)처럼 문제를 푸는 페이지가 아닌 것은 회 완료 판정 기준을 따로 정해 SPEC에 적은 뒤에 넣는다. 정하기 전에는 완료 판정에 포함하지 않는다.
6. 새 영역을 넣은 뒤에는 6개 학교 audit.py를 모두 돌려 PASS일 때만 반영했다고 말한다.

## 어휘 퀴즈 규칙 (261022)
- 다의어 보기는 그 단어 자체의 다른 뜻 문장만 쓴다. 다른 단어 문장으로 빈자리를 채우지 않는다. 다른 뜻이 하나뿐이면 보기는 2개.
- 한 단어의 뜻이 서로 겹쳐 정답이 둘이 될 수 있으면 x(제외 뜻)로 빼거나 뜻을 합친다.
- 뜻이 진짜 하나뿐인 단어는 다의어 문제로 내지 않는다.
- 유의어·반의어는 사전(thesaurus) 근거가 있는 것만. 정답 1개, 오답은 유의어가 아님을 확인한 같은 품사 단어.
- 화면에 나오는 영어 단어에는 한글 뜻을 붙인다. 보기 글씨 17px 이상(font 줄임식 `font:600 16.5px/1.4 inherit`은 무효라 쓰지 않는다).
- 문제 id(단어·문장)를 바꾸면 mix-pool.js와 index.html의 CNT 문항 수도 같이 고친다.
- 이미 학생이 푼 단원의 문제는 바꾸지 않는다. 새 규칙은 아직 안 푼 단원부터 적용.

## 정답·해설 페이지 규격 (261022)
- 빠른정답 목차(`id="quick"`)가 있는 모든 페이지는 같은 버튼 세트를 가진다: 왼쪽 아래 확인 버튼(PG.bar), 오른쪽 "▲ 빠른정답"(`id="fq"`, right:88px), 맨 오른쪽 "⌂ 목록"(`class="homefab"`).
- "▲ 빠른정답"은 문항 해설을 읽는 구간에서만 떠 있고(첫 문항이 화면 60% 안으로 오면 표시), 누르면 `#quick`으로 이동.
- 문항마다 되돌아가기 링크(`↑ 빠른정답` 또는 `▲ 빠른정답으로`)가 문항 수 이상이어야 한다. 금천고1 동사형은 `#k<N>`으로 가는 링크도 인정.
- 위 세 가지는 audit.py가 전 학교에서 검사한다. 페이지를 새로 만들거나 고칠 때 이 버튼 세트를 지우지 않는다.

## 학교 이름·학원 이름 (261022)
- 학교 폴더 안 화면(제목, 머리글, "← ○○고N 정답 목록", 푸터)에는 그 학교 이름만 쓴다. 다른 학교 이름이 남는 사고(복사 잔재)는 audit.py가 잡는다(폴더 안 html/js 전체 검사).
- 푸터는 "비타민 영어클리닉 · 학교명" 한 줄만. 목록 버튼이나 상단바에 학원 이름을 넣지 않는다(검토 후 보류: 목록 버튼이 커져 학생 시선을 끌어서).

## 풀코스유형별 20문항 · 풀코스 추가문제 · 오답노트 (261027)
- 이름: mix.html 제목(title·h1)과 목록 카드는 "풀코스유형별 20문항". 설명은 "풀코스 문제를 20문항씩, 또는 원하는 유형만 골라 풀어요. 나왔던 문제지만 회차에 매이지 않고 유형만 잡을 수 있어요." 그 아래 새 줄, 왼쪽 정렬로 "총 N문항 · 약 N회분"(class="nc", mix-pool.js 문항 합계, 20문항씩 올림). "전체 랜덤"·"랜덤 문제 풀기"·"스페셜 · 교과서 다지기" 표기는 쓰지 않는다.
- 풀코스 추가문제(dajigi.html, dajigi-data.js): 풀코스에 20회차로 균등하게 문제를 넣다가 미처 넣지 못한 문제를 따로 담는 코너. 풀코스 활동에 이미 있는 문제는 데이터에서 뺀다(어휘=같은 단어쌍, 문법=같은 빈칸 위치+정답). 문제를 새로 추가할 때도 같은 대조를 거쳐 데이터 맨 뒤에 붙인다.
- 풀코스 추가문제는 랜덤이 아니다: 데이터 순서대로 앞에서부터 20문항씩(문법·어휘 번갈아), 풀던 세트는 이어서 풀기, 끝까지 풀면 처음부터 다시. 화면에 총 문항·약 N회분·"랜덤이 아니라 담긴 순서대로"·푼 문항·남은 문항을 표시한다. 범위(3과·4과)·유형 칩을 골라도 그 안에서 순서를 지킨다. 새 문제는 뒤에 쌓인다.
- 오답은 따로 관리하지 않고 공통 오답노트로 간다: 틀리면 WN.add({kind:'dj',part:0,act:'dj',qid}). wrong.html은 qid 앞글자로 유형을 합쳐 보여 준다(g=어법선택 eobeop, v=어휘 voc; 함수 EA). 칩에 "추가문제"는 없고, 묶음 제목 아래 작은 글씨로 "풀코스 추가문제"만 표시. 풀기 주소는 dajigi.html?part=0&wrong=1&dt=eobeop 또는 dt=voc.
- index.html 나의 약점 TOP3(wk)도 추가문제 오답을 같은 규칙(EA)으로 어법선택·어휘에 합산한다.
- 6개 학교 모두 같은 파일 5개(index, mix, dajigi, dajigi-data, wrong)를 맞춘다. 추가문제 문항 수(261027): 금천고1 139, 금천고2 108, 주성고1 119, 주성고2 52, 청석고1 124, 청석고2 104.
- 올리기 점검: 파일마다 올린 뒤 사이트 해시를 올린 내용과 대조한다. 이날 금천고2 index와 주성고1 mix가 저장되지 않았고 청석고1 wrong은 한 번 저장이 안 된 사례가 있었다. 커밋 직후 주소가 /blob/ 로 바뀌었는지도 확인한다.

## 저장 키 계약: 앱 – 구글 시트 – 조회 화면 (261027)
세 조각의 관계: 학생 앱(폰 localStorage) -> rec.js -> 구글 시트+Apps Script(내용을 가리지 않고 키·값을 쌓기만 함) -> 선생님 조회 화면(h/rec/index.html, 폰 홈 화면 바로가기). 앱 기능을 바꿀 때 시트와 Apps Script는 보통 건드리지 않는다. 앱과 조회 화면이 맞물리는 곳은 **키 이름과 값 모양** 하나뿐이고, 그 약속이 아래 표다.
기준 앱: 금천고1(기본 틀), 주성고2(모의고사까지 들어간 틀). 모의고사 포함 앱은 주성고2를 따른다.

| 키 | 값 모양 | 쓰는 곳 | 조회 화면 |
|---|---|---|---|
| vhp:<학교> | {"구간:활동":{n,t}} n=끝낸 횟수, t=마지막 시각(ms) | common/prog.js(PG.mark) | 읽음: 누적 풀코스·누적 채점·마지막 시각 |
| vhd:<구간:활동> | 걸린 시간(초). 키에 학교 없음 | parts.js | 읽음: 누적 이용시간 보정(10/22 이전분) |
| vhc:<학교> | {"L3p1":"YYYY-MM-DD"} 회차 완료일 | index.html | 읽음: 마지막 회차 |
| vhw:<학교> | [{id,kind,part,act,qid,label,label2,t,w,c,star}] 오답노트. 추가문제 오답은 kind:'dj' | wrong.js | 읽음: 오답노트 개수(배열 길이) |

조회 화면에 보이는 항목과 출처: 누적 이용시간·오늘 이용시간(vhts, vhd), 누적 풀코스(vhp+CNP), 마지막 회차(vhc), 누적 채점(vhp+CNK), 오답노트(vhw), 풀코스 추가문제 N/전체(vhdj+DJT).

규칙
1. 새 키는 `vh<소문자>:<학교폴더>` 모양으로 만든다. `vh`로 시작해야 공용폰 모드(?shared=1, common/prog.js)가 가로채 폰에 남기지 않고, 학교 폴더가 들어가야 같은 폰에서 학교끼리 기록이 섞이지 않는다(모든 학교 앱이 같은 주소 nolbada.github.io를 쓴다). 값 한 줄이 45,000자를 넘으면 시트로 올라가지 않는다(rec.js MAXV).
2. 키 이름이나 값 모양을 바꾸면 **같은 날** 조회 화면(h/rec/index.html)에서 그 키를 읽는 줄도 고친다. 학생 폰에 이미 쌓인 옛 모양은 한동안 둘 다 읽는다.
3. 조회 화면에 새 숫자를 보이고 싶을 때만 조회 화면을 고친다. 구글 시트·Apps Script는 키와 값을 가리지 않으므로 고치지 않는다. 시트·Apps Script를 고치는 경우는 열을 늘리거나 값 길이 제한·반 코드 처리가 바뀔 때뿐이다.
4. 학교별 문항 수가 바뀌면 조회 화면의 숫자 표(CNK 풀코스 문항, CNP 풀코스 활동 문제 수, DJT 추가문제 수)도 같이 고친다. 추가문제를 늘리면 DJT를 고친다(261027: 금천고1 139, 금천고2 108, 주성고1 119, 주성고2 52, 청석고1 124, 청석고2 104).
5. 키를 새로 만들면 이 표에 한 줄을 넣고 tools/audit.py의 KEYMAP에도 넣는다. `python3 tools/audit.py --keys`(브라우저 없이 빠름)는 표에 없는 vh 키를 FAIL로, 조회 화면이 읽어야 할 키를 더 이상 읽지 않으면 FAIL로, vh로 시작하지 않는 새 키를 FAIL로 보여 준다(아래 동결 목록의 옛 키만 "주의"). 전체 검수(python3 tools/audit.py)에도 같은 점검이 들어 있다.
6. 조회 화면을 고쳐 올릴 때도 파일 하나만 올리고, 올린 뒤 사이트 해시를 대조한다(위 "올리기 점검").
